1. Введение в Control D

Control D -- это настраиваемый DNS-резолвер и платформа фильтрации трафика, который позволяет управлять интернет-соединением на уровне DNS-запросов. В отличие от обычных DNS-серверов (Google DNS, Cloudflare), Control D дает гранулярный контроль над тем, какие домены разрешаются, блокируются или перенаправляются.

TL;DR
Control D -- это DNS-сервис, который можно настроить под свои нужды: блокировать рекламу, защищать от вредоносных сайтов, перенаправлять трафик через прокси в 100+ локациях.

1.1 Что такое DNS

DNS (Domain Name System) -- это система, которая преобразует человекочитаемые доменные имена (например, google.com) в IP-адреса (например, 142.250.80.46). Работает как телефонная книга интернета:

ЭтапОписание
Запрос пользователяВводите example.com в браузере
УстройствоОтправляет запрос к DNS-резолверу
МаршрутизаторПересылает запрос настроенному DNS-серверу
DNS-провайдерОбрабатывает запрос (ISP, Google, Cloudflare, Control D)
Авторитативный серверВозвращает IP-адрес запрашиваемого домена

Обычно DNS-ответы статичны -- любой пользователь из любой точки мира получит одинаковый IP для одного домена. Исключение -- CDN, которые подбирают сервер ближе к вашей геолокации.

1.2 Как работает Control D

Control D предоставляет уникальные DNS-резолверы, которые могут манипулировать ответами на основе заданных правил. Вот что происходит при использовании:

  1. Резолюция: По умолчанию Control D работает как обычный DNS-резолвер -- разрешает домены в IP-адреса.
  2. Правила: Когда вы настраиваете фильтры, сервисы и кастомные правила, Control D начинает перехватывать DNS-запросы.
  3. Действия: Для каждого запроса применяется одно из действий:
    • BYPASS -- разрешить, вернуть реальный IP
    • BLOCK -- заблокировать (вернуть 0.0.0.0)
    • REDIRECT -- перенаправить через прокси в выбранной локации
Ключевая особенность
При перенаправлении (REDIRECT) Control D прозрачно проксирует SNI-трафик через серверы в выбранной локации. Сайт видит IP прокси, а не ваш реальный IP. Работает совместно с Windscribe (100+ городов).

2. Основные компоненты

Архитектура Control D строится вокруг нескольких ключевых компонентов. Понимание их взаимодействия -- основа эффективной настройки.

2.1 Профили (Profiles)

Профиль -- это набор правил и настроек, которые применяются к Endpoint. Аналогия: профиль = политика безопасности.

Каждый профиль содержит:

  • Filters -- категории для блокировки
  • Services -- правила для конкретных сервисов
  • Custom Rules -- гранулярные правила на уровне доменов
  • Profile Options -- дополнительные настройки поведения
Множественные профили
Можно создавать десятки профилей для разных сценариев: рабочий (блокировка отвлекающих сайтов), детский (безопасный поиск), персональный (свои правила). Каждый профиль назначается на отдельный Endpoint.

2.2 Фильтры (Filters)

Фильтры -- это готовые списки блокировки. Обновляются каждые 15 минут.

Нативные фильтры (Native Filters)

ФильтрОписаниеРежимы
Ads & TrackersРеклама и трекерыMinimal / Balanced / Aggressive
MalwareВредоносные доменыRelaxed / Balanced / Aggressive
PhishingФишинговые сайты--
SocialСоциальные сети--
GamblingОнлайн-казино, беттинг--
PornographyAdult-контент--
DrugsНаркотический контент--
VoIPIP-телефония--

Сторонние фильтры (3rd Party)

Более 10 популярных комьюнити-списков: Hagezi, OISD, 1Hosts, StevenBlack и др. Обновляются независимо от Control D, используются на свой страх и риск.

2.3 Сервисы (Services)

Сервисы -- это готовые коллекции доменов, принадлежащих конкретному сайту или приложению. Например, сервис facebook включает десятки доменов: facebook.com, fbcdn.net, instagram.com и т.д.

Для каждого сервиса можно задать одно из трех действий:

ДействиеКодОписание
BYPASS0Разрешить, использовать реальный IP
BLOCK1Заблокировать полностью
REDIRECT3Перенаправить через прокси (указать локацию, например JFK)
Более 400 сервисов
Control D поддерживает 400+ сервисов: от Amazon и Netflix до специфических банковских сервисов. Сервисные правила имеют приоритет над фильтрами -- если включен Social Filter (блокирует все соцсети), но для Instagram задан BYPASS -- Instagram будет работать.

2.4 Пользовательские правила (Custom Rules)

Кастомные правила -- базовые строительные блоки Control D. Позволяют создавать правила для конкретных доменов с поддержкой wildcard (*.example.com). Лимит: до 10,000 правил на профиль.

Типы правил:

  • Block -- домен не загрузится
  • Bypass -- игнорировать фильтры, вернуть реальный IP
  • Redirect -- подменить IP или проксировать через выбранную локацию
Приватные домены
Для создания приватных доменов (например, для Active Directory) используйте Redirect с указанием IP или hostname вместо прокси. Это позволяет использовать Control D как основной DNS в корпоративной среде.

2.5 Гео-правила (Geo Custom Rules)

Geo Custom Rules используют геолокацию IP-адреса источника или назначения для принятия решений.

Формат правил

ПрефиксЗначениеПример
@XXСтрана назначения@CN -- сайт хостится в Китае
!@XXНЕ страна назначения!@US -- сайт НЕ в США
@ASxxxxxASN назначения@AS16509 -- Amazon
#XXСтрана источника#CA -- запрос из Канады
!#XXНЕ страна источника!#DE -- запрос НЕ из Германии
Важное ограничение
Не смешивайте разные действия (Block, Bypass, Redirect) для "not-правил" (с !), иначе поведение будет непредсказуемым. Все not-правила одного типа должны иметь одно и то же действие.

2.6 Правило по умолчанию (Default Rule)

Специальное правило-ловушка, которое срабатывает, когда ни одно другое правило не подошло.

ДействиеРезультатКогда использовать
BypassРазрешить всё (по умолчанию)Стандартный режим -- блокируется только то, что явно указано
BlockБлокировать всёWhitelist-режим -- работает только то, что явно разрешено
RedirectПеренаправлять всё через проксиВсе запросы идут через выбранную локацию (например, JFK)
Осторожно с Redirect
Перенаправление всего трафика может сломать SSH, игры, VoIP-приложения и некоторые мессенджеры. Используйте с осторожностью и настраивайте bypass для проблемных сервисов.

3. Настройка и развертывание

3.1 Создание Endpoint

Endpoint -- это уникальный DNS-резолвер, который применяет профиль. Каждый Endpoint получает:

  • Уникальный ID резолвера
  • Адреса DoH / DoT / DoQUIC
  • Legacy DNS (IPv4/IPv6) -- опционально

1 В панели управления перейдите в раздел Endpoints
2 Нажмите зеленую кнопку +
3 Выберите тип устройства и операционную систему
4 Настройте параметры Endpoint (уровень аналитики, IP-авторизацию и т.д.)
5 Нажмите Create -- будут сгенерированы уникальные DNS-адреса

3.2 DNS-протоколы

ПротоколПортБезопасностьПоддержка
Legacy DNS (UDP 53)53НизкаяВсе устройства
DNS-over-HTTPS (DoH)443ВысокаяСовременные ОС
DNS-over-TLS (DoT)853ВысокаяСовременные ОС
DNS-over-QUIC (DoQ)853/QUICВысокаяЭкспериментальный
Рекомендация
Используйте DoH или DoT для шифрования DNS-запросов. Legacy DNS не шифруется и может быть перехвачен или подменен провайдером.

4. Профильные опции

4.1 Защита от DNS Rebinding

Блокирует домены, которые указывают на приватные IP-адреса (RFC1918). Защищает от атак, когда злоумышленник заставляет ваш браузер обращаться к внутренним ресурсам сети.

ДиапазонОписание
127.0.0.0/8Loopback (localhost)
10.0.0.0/8Приватные адреса Class A
172.16.0.0/12Приватные адреса Class B
192.168.0.0/16Приватные адреса Class C
169.254.0.0/16Link-local
fd00::/8IPv6 Unique Local

4.2 TTL Overrides

Позволяет переопределить время жизни DNS-записей для оптимизации:

Тип TTLПо умолчаниюЭффект увеличения
Block TTL10 секМеньше DNS-запросов для заблокированных доменов
Redirect TTL20 секМеньше запросов для перенаправленных доменов
Bypass TTLАвтоМеньше запросов вообще, но может ломать CDN

4.3 AI Malware Filter

ML-модель, которая классифицирует домены как вредоносные даже если их нет в блоклистах. Три режима:

РежимАгрессивностьЛожные срабатывания
MinimalТолько высокая уверенностьМинимум (рекомендуется)
StandardСредняя уверенностьУмеренное количество
AggressiveНизкая уверенностьМного (не рекомендуется)

4.4 Safe Search и Restricted YouTube

  • Safe Search -- принудительно включает безопасный поиск в Google, Bing, DuckDuckGo. Поисковики без поддержки блокируются.
  • Restricted YouTube -- включает ограниченный режим YouTube (скрывает взрослый контент и отключает комментарии).

4.5 EDNS Client Subnet

РежимОписаниеПриватность

AutoИспользовать подсеть Control D сервераСредняя
CustomУказать свою подсетьКонтролируемая

5. Приоритет правил

При совпадении нескольких правил для одного домена применяется правило с наивысшим приоритетом. Иерархия (от высшего к низшему):

ПриоритетТип правилаОписание
1 (высший)Custom RulesГранулярные правила для конкретных доменов
2ServicesПравила для сервисов (400+ готовых)
3FiltersКатегориальные фильтры
4Geo Custom RulesГео-логика
5Default RuleПравило по умолчанию (ловушка)
6 (низший)da (default action)Действие по умолчанию профиля
Пример приоритетов
Если включен Social Filter (блокирует все соцсети), но для сервиса instagram задан BYPASS, а для домена pixel.instagram.com задан BLOCK -- результат:
pixel.instagram.com будет заблокирован (Custom Rule выигрывает у Service Rule).
instagram.com будет разрешен (Service BYPASS выигрывает у Filter BLOCK).

6. Аналитика и мониторинг

Control D предоставляет детальную аналитику DNS-запросов:

Уровни аналитики

УровеньЧто собираетсяХранение
NoneНичего--
BasicАгрегированные данные90 дней
FullКаждый запрос: домен, время, протокол, действие, причина30 дней

Разделы аналитики

  • Statistics -- сводка использования, тренды, топ доменов
  • Activity Log -- точные DNS-запросы с метаданными
  • Status Page -- диагностическая информация: IP, протокол, задержка, авторизация прокси
Приватность данных
Максимально детальные данные (Full Analytics) хранятся не более 30 дней. Можно выбрать регион хранения (Storage Region). Гранулярные данные включают домен, время, протокол, DNS return code, тип записи, действие и причину.

8. Практические советы

Совет 1: Начните с профиля по умолчанию

Default Rule = BYPASS. Включайте фильтры по одному и проверяйте, что не ломается. Так проще откатить проблемное изменение.

Совет 2: Используйте сервисы вместо ручных доменов

Вместо перечисления десятков доменов Facebook используйте готовый сервис facebook -- он включает все необходимые домены и автоматически обновляется.

Совет 3: Настройте bypass для критичных сервисов

Банки, платежные системы, стриминг-сервисы -- лучше оставлять на BYPASS. Они чувствительны к геолокации и могут блокировать вход через прокси.

Совет 4: Проверяйте Status Page после изменений

https://controld.com/status покажет: используете ли вы Control D, какой протокол, задержку, авторизован ли прокси.

Совет 5: Используйте Geo-правила умно

Правило !@US -> REDIRECT JFK автоматически перенаправляет весь трафик на сайты, которые не хостятся в США. Это ключ к созданию "американского" профиля.

Совет 6: Группируйте правила в папки

Magic Folders позволяют группировать кастомные правила и применять действия ко всей папке сразу. Удобно для управления большим количеством правил.

Совет 7: Lock Profile для продуктивности

Включайте Profile Lock с паролем, если профиль используется для блокировки отвлекающих сайтов. Это добавляет трения перед изменением правил.

Совет 8: Мониторьте Activity Log

Регулярно проверяйте логи -- вы обнаружите неожиданные запросы от приложений и сможете настроить правила точнее.

9. Профили для Нью-Йорка

9.1 Философия JFK-профиля

JFK-профиль создает иллюзию нахождения в Нью-Йорке (JFK -- код аэропорта). Основной принцип: весь трафик идет через JFK, кроме явно прописанных исключений.

Архитектура профиля

СлойНазначениеДействие
ФильтрыБазовая защитаMalware + Ads + Typo + IoT -- ON
СервисыПеренаправление ключевых сервисовREDIRECT через JFK
Кастомные доменыТочечные правила для доменовREDIRECT/BYPASS/BLOCK
Geo-правилаАвтоматический редирект не-US трафика!@US -> REDIRECT JFK
Default RuleВсё остальноеREDIRECT через JFK

9.2 Структура JSON-профиля

Профиль Control D хранится в JSON-формате с следующей структурой:

{
  "name": "Название профиля",
  "profile": {
    "flt": {          // Фильтры
      "ads": { "do": 0, "status": 1, "lvl": "ads_medium" },
      "malware": { "do": 0, "status": 1 }
    },
    "cflt": [],       // Кастомные фильтры
    "ipflt": {        // IP-фильтры
      "ip_malware": { "do": 0, "status": 1 }
    },
    "rule": [         // Доменные правила (Custom Rules)
      {
        "PK": "domain.com",
        "order": 37,
        "group": 3,
        "action": { "do": 3, "status": 1, "via": "JFK" }
      }
    ],
    "geo_custom_rules": [  // Гео-правила
      {
        "id": "geo_not_us",
        "order": 3,
        "condition": { "country_not": ["US"] },
        "action": { "do": 3, "status": 1, "via": "JFK" }
      }
    ],
    "svc": {          // Сервисные правила
      "google": { "type": "svc", "action": { "do": 3, "status": 1, "via": "JFK" } }
    },
    "grp": [          // Группы
      {
        "PK": 6,
        "group": "Geo Custom Rules",
        "action": { "status": 1, "do": 3, "via": "JFK" }
      }
    ],
    "da": { "do": 1, "status": 1 }  // Default Action
  }
}

9.3 Готовый профиль NY-GCR

Ниже описан полный профиль для маскировки под Нью-Йорк. Файлы профилей включены отдельно.

Фильтры (включены)

  • Malware -- блокировка вредоносных доменов
  • Ads & Trackers -- блокировка рекламы (medium)
  • Typo Squatting -- защита от тайпсквоттинга
  • IoT Telemetry -- блокировка телеметрии
  • Hagezi Pro++ -- расширенный блоклист
  • OISD -- базовый блоклист

Сервисы (REDIRECT через JFK)

Более 60 ключевых сервисов перенаправляются через JFK: Google, YouTube, Instagram, Facebook, WhatsApp, Telegram, Claude, ChatGPT, Bing, Microsoft, PayPal, Spotify, Amazon, AWS, Cloudflare и многие другие.

Исключения (BYPASS)

Следующие сервисы оставлены в обход для совместимости:

  • VPN-сервисы (Windscribe, AdGuard VPN) -- нужны для дополнительной защиты
  • Некоторые китайские сервисы -- для доступа к региональному контенту

Кастомные доменные правила

Дополнительные правила для доменов Meta, Google API, Instagram analytics и других:

  • lookaside.facebook.com -> REDIRECT JFK
  • graph.instagram.com -> REDIRECT JFK
  • *.fbcdn.net -> REDIRECT JFK
  • *.meta.com -> REDIRECT JFK
  • geolocation.googleapis.com -> BYPASS

Geo-правило

IF страна назначения != "US" THEN REDIRECT через JFK

Это автоматически перенаправляет весь трафик на сайты, хостящиеся за пределами США, через Нью-Йоркский прокси.

Default Rule

universal-all -> REDIRECT через JFK

Все, что не попало в предыдущие правила, автоматически перенаправляется через JFK.

10. Заключение

Control D -- это мощный инструмент для управления DNS-трафиком, который выходит далеко за рамки обычного DNS-резолвера. Ключевые преимущества:

  • Гранулярный контроль -- правила на уровне доменов, сервисов, стран и ASN
  • Прозрачное проксирование -- маскировка IP через 100+ локаций без VPN
  • ML-защита -- блокировка угроз в реальном времени
  • Никакого софта -- работает через нативные DoH/DoT в современных ОС
  • Бесплатный уровень -- базовая фильтрация без регистрации

JFK-профиль, описанный в этом гайде, создает полную иллюзию нахождения в Нью-Йорке: все DNS-запросы разрешаются через американскую инфраструктуру, трафик выходит через JFK-прокси, geo-правила автоматически перенаправляют не-US трафик. Это эффективное решение для тех, кому нужна американская цифровая идентичность.
